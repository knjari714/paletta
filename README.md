# Paletta（パレッタ） v0.4.0 β

**数学の学び方を、自分の色に。**

Paletta は、数学の勉強方法を振り返り、自分に合った学び方を見つけるための無料Webアプリです（β版）。
個人開発・個人運営（開発・運営：新井健使）。特定の学校・教育委員会の公式サービスではありません。

ビルド作業は不要です。`public/` フォルダをそのまま公開すれば動きます。

---

```

  js/app.js             アプリ本体（通常は編集不要）
  js/pages.js           案内ページ用の小さな補助（なくても本文は読めます）
  data/                 ★ 内容データ。ここを編集します
    config.js           アプリ名・キャッチコピー・版・運営者・お問い合わせURL・科目・カードの種類
    navi.js             困り感、問い、分岐、結果（候補カードの組み合わせ）

  icons/                ファビコン・ホーム画面用アイコン

  manifest.webmanifest  ホーム画面に追加したときの名前・アイコン

dev/                    開発用（公開されません）
  check.html            データ確認ページ（分岐・カードの参照チェック、全文書き出し）
  logo-source/          ロゴの元画像（original）と、小さなゴミを除去した版（clean）
  tests/                自動テスト一式
    run_all.sh          すべてのテストを実行
    test_learning.py    学習機能（セルフナビ全21分岐・カード21枚・記録・互換性など）
    test_return.py      カード詳細から元の画面に戻る機能
    test_v04.py         v0.4 の追加分（案内ページ・お問い合わせ・名称・PWA・公開ファイル）
    fixtures/           v0.1〜v0.3 で書き出した記録ファイル（互換性テスト用）
```

## 公開方法（Netlify）

**v0.4 からフォルダ構成が変わったため、公開時に次を確認してください。**

1. リポジトリの中身を、このフォルダ構成（`netlify.toml`・`public/`・`dev/`・`README.md`）に置き換えて GitHub に反映します。
2. `netlify.toml` に `publish = "public"` と書いてあるため、`public/` だけが公開されます。このファイルの設定は、Netlify 管理画面の Build settings より優先されます。
3. 公開後、次の URL を確認します。
   - `https://（アプリのURL）/` … Paletta が開く
   - `https://（アプリのURL）/howto.html` など … 案内ページが開く
   - `https://（アプリのURL）/check.html` … **開かない（404）** こと
4. 以前の版を使っていた端末では、次に開いたときに新しい版へ自動で切り替わります（古いキャッシュは削除されます）。

### 公開前に Netlify 管理画面で確認すること

プライバシーポリシーの記述と一致させるため、次がオフ（未使用）であることを確認してください。使う場合は、プライバシーポリシーの改訂が必要です。

- Analytics（Netlify Analytics）
- Real User Metrics（Observability などの名称の場合もあります）
- Forms（フォーム検出）… 今回は使用しません
- Snippet injection（Site configuration → Build & deploy → Post processing）
- そのほか、外部スクリプトを追加する設定・プラグイン
- アクセスログ（Logs）：どの情報をどの程度見られるか（プランによって異なります）

### プライバシーポリシーの記述と、確認する設定の対応

`public/privacy.html` の次の節は、公開環境の設定と一致している必要があります。設定を変えた場合は、ポリシーも見直してください。

| privacy.html の節 | 一致させる設定 |
|---|---|
| 4. アクセス時に扱われる情報 | Netlify の Analytics・Real User Metrics・Forms・Snippet injection が無効であること、アクセスログの扱い |
| 6. Cookie・アクセス解析について | Netlify の Snippet injection やプラグインなどで、アクセス解析や Cookie を使うスクリプトを追加していないこと |
| 7. お問い合わせ情報の取り扱い | Googleフォームの質問項目と「メールアドレスを収集する」などの回答者情報の収集設定 |

### Googleフォームで確認すること

- 回答者のログインを必須にしない（中高生や学校外の人が送れるように）
- 「メールアドレスを収集する」をオフにする（返信用のメールアドレスは任意の質問として設ける）
- 質問項目が、プライバシーポリシー「7. お問い合わせ情報の取り扱い」の内容と一致している
  （お問い合わせの種類／お名前・ニックネーム（任意）／メールアドレス（任意）／お問い合わせ内容／端末・ブラウザなど（任意））
- フォームの説明文に「名前や学校名など、個人が特定される情報は書かないでください」と添える
- 回答の通知メールの受け取り設定
- フォームのURLを変えた場合は、`public/data/config.js` の `contactUrl` と、案内ページ3つ（各ページ下部・本文）のリンクを書き換える

## 名称を変えるとき

アプリ画面の名称は `public/data/config.js` の `appName` などで変わります。
案内ページはJavaScriptなしでも読めるように名称を直接書いているため、次のファイルも合わせて直してください。

- `public/index.html`（`<title>`・meta）
- `public/manifest.webmanifest`
- `public/howto.html`・`terms.html`・`privacy.html`
- ロゴ画像（`public/images/`）・アイコン（`public/icons/`）

**保存キー（`manabikata-note.v1` など `manabikata-` で始まる名前）は変えないでください。** 変えると、これまでの記録が読めなくなります。

## 公開のたびにすること

- `public/sw.js` の `CACHE` の名前を変える（例：`paletta-v0.4.1`）。古いキャッシュが確実に削除され、新しい内容が表示されます。
- `public/data/config.js` の `version`・`versionLabel` と、案内ページ下部の版の表示を更新する。
- 利用規約・プライバシーポリシーの「制定日：【公開日】」を、実際の日付に置き換える（初回公開時）。改訂した場合は「最終改定日」を追記する。

## 内容の直し方

`public/data/` のファイルは、プログラムの知識がなくても読めるように、各ファイルの先頭に書き方の説明があります。
ChatGPT などに相談する場合は、該当ファイルの中身をそのまま貼り、「形式を変えずに文面を直して」と頼むと安全です。

### データ確認ページ（check.html）

文面や分岐を直したら、`dev/check.html` をブラウザで開いてください（ファイルをダブルクリックで開けます）。v0.4 から、check.html は公開サイトには含まれません。次のことがわかります。

- 分岐の行き先やカードの id の書き間違い、カンマ抜けなどで読み込めないファイル
- 候補カードが2〜3枚になっていない分岐や、どこからも使われていない問い
- **分岐の全体一覧**：Q1 → Q2 → 受け止め → 自分への問い → 候補カード
- 各カードが、いくつの分岐で候補になっているか
- 分岐全体のテキスト書き出し（ChatGPT などに貼って検討するときに使えます）

### よくある編集

- **問いの文面を変える**：`navi.js` の `text` や `label` を書き換えます。
- **分岐を変える**：選択肢の `goto: "問いのid"`（次の問いへ）か `result: "結果のid"`（自分への問い・候補へ）を書き換えます。
- **自分への問い・受け止めの文を変える**：`navi.js` の `results` にある `ask`（自分への問い）、`echo`（答えの受け止め）、`encourage`（添える一言・任意）、`lead`（候補とのつながり）を書き換えます。
- **候補に出すカードを変える**：`navi.js` の `results` にあるカードの id の並びを変えます。書いた順に表示されます。
- **「誰かと取り組む方法も見る」に出すカードを変える**：`navi.js` の `results` の `others` に、カードの id を書きます。関係の深い分岐だけに書いてください。書かなければ、ライブラリへの案内が表示されます。
- **カードの種類を変える**：`cards.js` の `category`（"study"／"math"／"others"）と `mode`（"solo"／"either"／"withOthers"）を書き換えます。種類の表示名と説明は `config.js` の `categories` にあります。
- **「ここまででもOK」「余裕があれば」「補足」を足す**：`cards.js` に `easyStart`、`extension`、`note` を書きます。書かないカードでは表示されません。
- **研究用のタグ**：`cards.js` の `researchTags` は生徒の画面には表示されません。check.html の一覧で確認できます。
- **カードを追加する**：`cards.js` に項目を1つ足し、`navi.js` の `results` からその id を参照します。
- **困り感を追加する（例：Small Start）**：`navi.js` の `concerns` で `available: true` にし、`start` に最初の問いの id を書きます。カードは `type: "start"` にすると、ライブラリで Small Start として絞り込めます。

### 注意点

- 文字列は `"` で囲み、項目の間には `,` が必要です。カンマが抜けると、アプリが表示されなくなります。
- 振り返りの選択肢の `value` は記録に保存されます。すでに使っている人がいる段階では、`label` だけを変え、`value` は変えないでください。
- 既存カードの `id` は変えないでください。過去の記録が参照しています。
- 内容を直したら、手元のブラウザで `dev/check.html` と `public/index.html` を開いて確認できます。

## テストの実行

Python3・Playwright（Chromium）・Node.js が必要です。プロジェクトのルートで次を実行します。

```
sh dev/tests/run_all.sh
```

ローカルにサーバーを起動し、`public/` のアプリと `dev/check.html` を自動で操作して確認します。

## 記録の保存について

記録は利用者の端末のブラウザ内（localStorage）に保存され、運営者には送られません。
ログインは不要で、運営者が記録を見る仕組みもありません。
ブラウザのデータ削除や端末の変更に備えて、アプリ内の「記録の保存と引き継ぎ」から書き出しができます。

## 今後の拡張のための準備

- 記録には `subject`（科目）が任意で付いています。将来の学習データ機能で集計に使えます。
- 記録には、選んだときの問いへの答え（`answers`）も残しています。「どの困り感から、どの方法が選ばれ、どう振り返られたか」をたどれます。
